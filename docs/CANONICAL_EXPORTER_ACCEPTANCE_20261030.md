# Canonical publication exporter — 30 October 2026

The existing monthly register exporter now also queries the retained Power BI
model and writes full and monthly canonical CSV/HTML plus a completion manifest
to its existing owner-only SharePoint reporting folder. It uses the original
SharePoint binding and the writer's existing Power BI binding. Source acquisition,
model refresh, registry writes and email are outside this flow.

The user explicitly authorised deployment, verification and unchanged replay.
The accepted verification run reconciled all 18 fields for 1,344 full records and
14 September 2026 records, independent full/month key queries and count queries,
and the saved manifest. Native content readback matched the generated bytes.
The selected revision is `v2`; filenames are `canonical-2026-09-v2-full.csv`,
`canonical-2026-09-v2-full.html`, `canonical-2026-09-v2-month.csv`,
`canonical-2026-09-v2-month.html` and `canonical-2026-09-v2-complete.json`.

The unchanged replay also succeeded. All five canonical create actions were
skipped; bytes, ETags, modification timestamps, lengths and version 1.0 remained
identical. Both runs independently reconciled the full/month key sets and counts.
Private `acceptance.json`, `verification-v4-complete-acceptance.json`,
`replay-v4-complete-acceptance.json` and before/after metadata retain the proof.

The exporter resolves the previous completed Brisbane month once per run.
Immutable create-only output preserves existing and human-edited files; equal
content is an unchanged replay, while different content requires an explicit
new revision. The existing register snapshot still creates its normal per-run
files. Do not describe the entire flow as write-free on canonical replay.

Native verification identified and repaired three concrete differences from
local expression checks: connector-backed Parse JSON rejects regex patterns;
the Power BI convenience `firstTableRows` omits null fields; and native prefix
comparison with invisible characters added apostrophes to ordinary CSV cells.
Validation now uses supported native predicates, the complete `includeNulls`
result table, and escaped control prefixes. Error/partial/truncation checks,
source invariants and independent key/count reconciliation remain enforced.
The first `v1` diagnostic output is retained, not overwritten or accepted.

Deployment used the retained PAC workload and a guarded same-record update.
Each update had a stopped, inactive preimage and exact saved-definition readback;
the original Started state and recurrence were restored. The monthly schedule
remains day 1 at 09:00 Brisbane, starting 1 November 2026. The independent monitor
remains at 12:05. Exporter failure emails and the weekly failure digest were
suppressed before the authorised runs. No source refresh or email was sent;
the two newer PubMed records remain deferred.
