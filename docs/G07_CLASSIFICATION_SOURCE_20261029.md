## Review and recovery semantics

Classification means exact source-code transport, not substantive opportunity
approval, source admission, applicant eligibility or permission to send.
`apply_mapping` adds only FunderKey, CategoryKeysJSON and
ClassificationEvidenceJSON. Existing assignments need explicit reconciliation;
forged mappings, changed response bytes or stale evidence fail. Original source
facts and human ReviewStatus are preserved, including Needs Review.

A changed canonical evidence hash or changed raw-response bytes invalidates the
old classification, clearing the current funder/categories while returning the
full previous mapping and invalidation journal. Cross-opportunity replacement
or concurrent classification edits refuse the transition. Even a raw formatting
change remains observable; it is not silently relabelled unchanged.

Replacement source-code preparation requires the exact invalidation preimage and
new response hash, then remaps only explicit source codes. It does not reset or
approve a human decision. `inspect_classification` always returns
`delivery_ready=false`, even for current classification and an already Reviewed
record. Projection refuses stale classification but does not authorise native
persistence or delivery. Audit key coverage likewise never grants provenance,
propagation or activation acceptance.

All mapping/invalidation tests use invented local records and supplied synthetic
bytes. No provider change, real source review, native classification save or
current-day service result is claimed. The accepted original canonical promotion
receipts remain historical evidence; these tests do not repeat or replace them.
