# GrantConnect daily browser intake

Run once per day in BrowserOS neo using the public browser profile. This is a Codex automation. Power Automate's manual RSS collector is stopped because its RSS connector received HTTP 403.

1. Start in canonical main. Use a new ignored private/ops occurrence directory. Read the previous accepted register and the existing private site/list binding. The initial generation is grantconnect-browser-20261101. Acquire the public RSS XML from the official URL in scripts/grantconnect_rss.py using the existing browser source-byte capture skill. Retain exact bytes, final URL, UTC time, size, headers and SHA-256. A 403, malformed response or incomplete capture leaves the last accepted register intact.
2. Use the repo-local Python to run scripts/grantconnect_rss.py bootstrap-xml with the pinned capture hash and new register output. Compare source ID, URL, title and description by OpportunityKey to the previous generation. Retain unchanged existing observations and evidence hashes. Archive the whole new capture. Import newly seen records as Needs Review using the existing cloud artifact upload and guarded grantconnect-register mode. Hold amended records for reconciliation when an existing version conflicts. Retain records absent from the current list.
3. From a same-origin public GrantConnect browser tab, fetch only the official URLs in that register. Omit credentials, refuse redirects, cap timeouts and batch requests. Read the direct span label and .list-desc-inner value inside each .list-desc. Capture key, url, status, ids (GO ID:), close (Close Date & Time:) and at (UTC). Preserve the page results privately. Match the GO ID and exact source URL before accepting the labelled ACT local timestamp. Ongoing means no confirmed closing date. A missing or conflicting field stays unresolved.
4. Run python -m scripts.grantconnect_closings REGISTER PAGES OUTPUT. Use the existing guarded grantconnect-calendar mode with REGISTER, OUTPUT and a fresh journal directory. Reconcile any interrupted intents to native rows before further writes. If an existing confirmed date has become ongoing, hold that change for explicit reconciliation until its old deadline has been retired. Never infer withdrawal from feed absence.
5. Process only Grants Registry and Funding Calendar after changed native rows. Read back the affected keys, UTC closing instants, calendar source dates and revisions once. Retain the receipt and promote the complete generation as the next baseline. On an access or version conflict retain the journal and report the affected scope. NIH remains inactive.

The register tracks source observations and stable opportunity keys. Application decisions and institutional review belong in separate reviewed records. Historical closed opportunities and awarded grants need distinct official sources and identifiers. Reconciliation to DoRA, ethics, people and publications requires reviewed evidence.

The browser expressions are in scripts/grantconnect_browser.js. Call captureGrantConnectFeed(), then read window.gcBytes in base64 chunks of 60,000 bytes and concatenate into the capture base64 field. All intermediate chunk lengths must be multiples of three bytes. The XML bootstrap verifies the assembled length and SHA-256. Call captureGrantConnectPages(rows) for up to ten official rows at a time. Preserve a private append-only occurrence journal. The initial private binding includes both list URLs.

For subsequent generations, pass --previous-register PREVIOUS_ACCEPTED_REGISTER to bootstrap-xml. Equal source facts keep their established EvidenceHash and first retained observation time. Changed source facts are archived and flagged for reconciliation. Do not replace an accepted baseline with a partially applied batch.
