# GrantConnect Power Automate options

The official feed returned XML anonymously in BrowserOS. The same URL returned CloudFront HTTP 403 to the CLI and Microsoft RSS connector. The precise upstream filtering rule is unknown. The one manual native run stopped at ListFeedItems. Replaying that flow with the same connection has no demonstrated benefit.

1. **Recommended now.** Keep the working browser collector and let Power Automate consume a completed SharePoint generation. Publish the immutable capture first, then create a small ready manifest with its SHA-256, count and generation ID. Scope the standard SharePoint file-created trigger to the ready folder and use Get file content. Reconcile the generation against an idempotency ledger before writing. Transfer sole downstream write ownership at cutover to avoid duplicating the existing CLI worker. This option retains browser acquisition and makes the cloud flow responsible for orchestration. [Microsoft SharePoint connector](https://learn.microsoft.com/en-us/connectors/sharepoint/)
2. **Preferred for direct RSS if supported by Finance.** Ask GrantConnect whether the XML URL supports Microsoft-hosted RSS requests and whether it offers a supported endpoint or a narrowly scoped allowlist. Supply the retained connector UTC timestamp and request ID privately. After Finance confirms a change, one bounded FlowAgent run can qualify the endpoint before activation. [GrantConnect contact and service description](https://www.finance.gov.au/individuals/find-grant-grantconnect) · [Microsoft RSS connector](https://learn.microsoft.com/en-us/connectors/rss/)
3. **Publisher notification fallback.** Finance offers applicant notifications for matching new opportunities. A mailbox-triggered flow could retain and reconcile authentic notifications against the register once their actual contents and coverage are known. This cannot establish historical coverage, and amendments, closures and withdrawals need separate evidence.
